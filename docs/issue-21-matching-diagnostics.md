## 新增证据及解释方式

匹配入场用例及独立 spinner 用例在原有真实点击和断言外保存 `matching-diagnostics-*` JSON 附件。准备阶段取消、正式录屏后取消、最终清理前均保存；因此正式录屏开始前超时也有诊断。正常运行同样保存，便于同构建对照。

点击附件只保存固定目标 testID、位置、可见/可用状态、目标采样 UTC、实际请求点击 UTC、驱动返回/失败时间及 UI 连接提示布尔值。普通 `tap` 的观测回调使用原有最后一次树查询，不新增查询、等待或点击；观测接收坐标副本。录屏入场沿用现有提前读取的位置，单独保留位置采样时间，连接提示记为未知；本轮不在无证据时修正该路径的同步逻辑。

`driver=returned` 只说明 Appium 调用返回。`modal.assertion=passed/failed` 是另一个独立事件，保留原有出现/消失断言及等待时限。本仓库当前测试驱动不能观测固定发布包的应用 JS 取消回调和内部连接枚举，明确输出 `appCallback=unknown`、`appConnectionState=unknown`。这不证明应用本身不存在其他遥测接口。UI 的 Connecting/Timeout 提示和代理 socket open/closed 不能替代应用内部状态。即使 quit 与点击时间接近，也不能仅凭时间相关性认定回调成功。

`transport.matchingRpc` 记录 staging 白名单中的 `/v1/hall_matching/join`、`quit`、`keep_waiting`：

| 字段/事件 | 可证实内容 |
| --- | --- |
| request / clientToProxy | 代理观测到该请求，包含 HTTP 方法；WebSocket 还记录 RPC 方法 9。不能据此声称上游已收到 |
| response / upstream | HTTP 状态，或同连接同 RPC ID 的真实 WebSocket reply/protocol-error；仅保留严格布尔业务 ok |
| response / proxy | 原有 HTTP 夹具响应，或原有 `inject.websocket` 调用返回；注入回执不代表客户端收到或执行回调 |
| incomplete / connection-closed | 观测到请求后连接结束，尚未观测到匹配回复；不伪装成业务成功或应用超时 |
| incomplete / transport-error | HTTP error 钩子结束请求且没有响应对象；来源、响应方向和业务 ok 均未知，不能计为真实上游回复 |
| incomplete / injection-failed | 匹配夹具的注入调用抛出异常；记录来源 proxy，但送达方向和业务 ok 未知，保留原始异常，不重试、不重放 |
| pending | 当前窗口内请求尚无关联响应，不能据空列表证明历史请求不存在 |

每次请求输出本地递增 sequence；WebSocket connection 编号与传输连接快照一致。真实 RPC ID 和 flow ID 仅留在有界内存关联表，不输出到附件。重连后复用的 RPC ID 不会误关联旧连接。UTC 与 `agoMs` 可将点击、驱动返回、请求、响应和连接关闭按同次测试排列；不是服务端时钟或送达证明。

计数按方法、路径、传输、方向、阶段、来源和状态累计；事件保留最近 256 项、待响应关联保留最近 128 项。`eventTotal` 与 `pendingEvicted` 标明历史裁剪。只解析最多 256 KiB 的文本消息、每条最多 1000 个 JSON 行；二进制、无效 JSON、非匹配路径及注入消息不当作真实 RPC。超出这些边界或代理未观测到流量时必须保持未知。

不记录账号、凭据、令牌、请求/响应正文、错误描述或关闭原因；只读取 RPC 路径、方法、关联号及响应状态。观测器不修改 flow、消息、请求或响应。已有匹配夹具仍按原逻辑隔离队列并模拟成功，正常及错误上游响应的单元测试则保持透传，二者不得混为真实服务验证。
